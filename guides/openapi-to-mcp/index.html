LOCAL API COMPILER

Compile OpenAPI into local MCP tools

Turn a supported OpenAPI3 definition into direct API tools with explicit input mappings and a local stdio server.

Documented Format-specific compiler contract

Accepted input

An OpenAPI3 JSON or YAML definition. Use an HTTPS server URL in the definition or supply --base-url. Bundle external references before compilation.

What the compiler produces

  • GET, POST, PUT, PATCH and DELETE operations become named tools. Unique operationIds are used when provided.
  • Path and query parameters become typed tool inputs. JSON request bodies are mapped into the outgoing request.
  • Supported authentication definitions produce environment-based API-key, bearer, Basic or OAuth token requirements. The compiler does not obtain OAuth tokens.

Output is a connector manifest containing named tools, method/path mappings, input schemas and environment-based authentication requirements. Compilation runs locally; it does not upload the definition, call provider operations or create a hosted account.

Local compiler interface

The recorded public compiler release contains this local interface. Requires Node.js22 or later.

git clone https://github.com/jannikco/openapi-to-mcp.git
cd openapi-to-mcp
npm ci --ignore-scripts
npm test
npm start
npm start -- ./api.yaml --base-url https://your-api.example.com --output my-connector.json
node server.mjs --manifest my-connector.json

The default npm start compiles the bundled fixture offline. Your own file replaces that fixture. Choose your real HTTPS API origin and keep credentials out of the definition.

After reviewing the generated manifest, launch its server with stdio transport in your MCP client. Supply the environment fields named by its auth object. External writes remain disabled unless CONNECTOR_ALLOW_WRITES=true and the specific call carries explicit _approval.

Compiler tests exercise fixtures and runtime request handling. Successful compilation is not a Live provider-operation result.

Supported boundary

  • Only JSON request bodies are handled by this compiler; unsupported bodies require a reviewed adapter.
  • External references must be bundled. Required custom headers, formData and cookie parameters need an explicit adapter.
  • An imported schema is not evidence of provider authentication or successful operation execution.

Source and release evidence

This guide follows compileDefinition(format, text, options) in the reviewed local compiler and the format-specific compile.mjs wrapper. The wrapper accepts an input file, --base-url and --output; the server accepts --manifest.
