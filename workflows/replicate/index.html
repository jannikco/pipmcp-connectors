Replicate WORKFLOW

Approve and inspect a prediction

Inspect the chosen model schema, approve prediction creation, then use the returned prediction ID to read status. Do not infer model success from the request transport result.

Documented Workflow definition · 3 real tool steps
Import with PipMCP ↗

Prerequisites and sequence

Obtain an authorized Replicate bearer token. Requests send it in the Authorization header.

  1. get_model — Inspect model metadata and latest_version.openapi_schema before constructing input.
  2. create_prediction — Start a billable asynchronous prediction after explicit approval. Read status/output with get_prediction; model-specific input must match its schema.
  3. get_prediction — Read prediction status, error and output metadata; starting/processing are not terminal success.

The definition references existing connector operations in the order above. Individual-step evidence does not establish that the composed workflow has been executed successfully. Inspect each result before continuing, and explicitly authorize any write step.

Run the local connector

Open source, with your own provider credentials. Provider API access and any provider charges remain yours. No PipMCP account is required for local execution.

Node.js22+ · terminal
git clone https://github.com/jannikco/replicate-mcp.git
cd replicate-mcp
npm ci --ignore-scripts
npm test
npm start

The default command shows the available operations offline. Provide REPLICATE_API_TOKEN through environment variables or the supported local OS-vault resolver.

For a stdio MCP client, launch npm run server in the checkout. Open the released connector for full client configuration →
