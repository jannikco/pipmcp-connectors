Cloudflare WORKFLOW

Zone access review

Verify a least-privilege token and inspect the domains it can access before changing DNS.

Documented Workflow definition · 2 real tool steps
Open PipMCP setup ↗

Prerequisites and sequence

Obtain an authorized Cloudflare bearer token. Requests send it in the Authorization header.

  1. verify_token — Check token validity without exposing its value.
  2. list_zones — List DNS zones allowed by this token.

The definition references existing connector operations in the order above. Individual-step evidence does not establish that the composed workflow has been executed successfully. Inspect each result before continuing, and explicitly authorize any write step.

Run the local connector

Open source, with your own provider credentials. Provider API access and any provider charges remain yours. No PipMCP account is required for local execution.

Node.js22+ · terminal
git clone https://github.com/jannikco/cloudflare-mcp.git
cd cloudflare-mcp
npm ci --ignore-scripts
npm test
npm start

The default command shows the available operations offline. Provide CLOUDFLARE_API_TOKEN through environment variables or the supported local OS-vault resolver.

For a stdio MCP client, launch npm run server in the checkout. Open the released connector for full client configuration →
