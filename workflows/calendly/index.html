Calendly WORKFLOW

Calendly authorized workflow

Identify the authenticated scheduler, inspect event types and explicitly create a one-use scheduling link.

Documented Workflow definition · 3 real tool steps
Open PipMCP setup ↗

Prerequisites and sequence

Obtain an authorized Calendly bearer token. Requests send it in the Authorization header.

  1. calendly_get_current_user — Read the authenticated user URI needed for event-type lookup.
  2. calendly_list_event_types — Read event types owned by the chosen authenticated user URI.
  3. calendly_create_single_use_link — Create a scheduling link limited to one event; plan/access requirements apply.

The definition references existing connector operations in the order above. Individual-step evidence does not establish that the composed workflow has been executed successfully. Inspect each result before continuing, and explicitly authorize any write step.

Run the local connector

Open source, with your own provider credentials. Provider API access and any provider charges remain yours. No PipMCP account is required for local execution.

Node.js22+ · terminal
git clone https://github.com/jannikco/calendly-mcp.git
cd calendly-mcp
npm ci --ignore-scripts
npm test
npm start

The default command shows the available operations offline. Provide CALENDLY_ACCESS_TOKEN through environment variables or the supported local OS-vault resolver.

For a stdio MCP client, launch npm run server in the checkout. Open the released connector for full client configuration →
