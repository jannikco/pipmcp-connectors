Grafana WORKFLOW

Inspect a dashboard and record an approved release annotation

Inspect a dashboard and record an approved release annotation. Read provider data first, then explicitly approve the selected change with operator write opt-in and a unique per-call approval key.

Documented Workflow definition · 3 real tool steps

Prerequisites and sequence

Obtain an authorized Grafana bearer token. Requests send it in the Authorization header.

  1. search_dashboards — Search dashboards.
  2. get_dashboard — Get dashboard.
  3. create_annotation — Create annotation.

The definition references existing connector operations in the order above. Individual-step evidence does not establish that the composed workflow has been executed successfully. Inspect each result before continuing, and explicitly authorize any write step.

Open provider authentication, permissions and all operations →

Run the local connector

Open source, with your own provider credentials. Provider API access and any provider charges remain yours. No PipMCP account is required for local execution.

Node.js22+ · terminal
git clone https://github.com/jannikco/grafana-mcp.git
cd grafana-mcp
npm ci --ignore-scripts
npm test
npm start

The default command shows the available operations offline. Provide GRAFANA_TOKEN through environment variables or the supported local OS-vault resolver.

For a stdio MCP client, launch npm run server in the checkout. Open the released connector for full client configuration →
