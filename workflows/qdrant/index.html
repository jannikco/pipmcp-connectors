Qdrant Cloud WORKFLOW

Inspect and update vector records

List collections, query a supplied vector, and only after reviewing point IDs approve an upsert into the same collection. Re-query to inspect provider results; dimensions and collection access remain provider-enforced.

Documented Workflow definition · 3 real tool steps
Import with PipMCP ↗

Prerequisites and sequence

Follow Qdrant Cloud's official authentication guide before connecting credentials. The required authorization flow must be confirmed for your account.

  1. list_collections — List collections on the configured Qdrant Cloud cluster.
  2. query_points — Read nearest points for a numeric query vector. Vector dimension must match the selected collection.
  3. upsert_points — Explicitly approved point insertion/update. Existing IDs are overwritten; acknowledged is not proof an asynchronous operation completed.

The definition references existing connector operations in the order above. Individual-step evidence does not establish that the composed workflow has been executed successfully. Inspect each result before continuing, and explicitly authorize any write step.

Run the local connector

Open source, with your own provider credentials. Provider API access and any provider charges remain yours. No PipMCP account is required for local execution.

Node.js22+ · terminal
git clone https://github.com/jannikco/qdrant-mcp.git
cd qdrant-mcp
npm ci --ignore-scripts
npm test
npm start

The default command shows the available operations offline. Provide QDRANT_API_KEY through environment variables or the supported local OS-vault resolver.

For a stdio MCP client, launch npm run server in the checkout. Open the released connector for full client configuration →
