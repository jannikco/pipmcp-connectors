GitHub Projects WORKFLOW

Summarize project work then link an approved existing issue or pull request

Summarize project work then link an approved existing issue or pull request. Read provider data first, then explicitly approve the selected change with operator write opt-in and a unique per-call approval key.

Prerequisites and sequence

Obtain an authorized GitHub Projects bearer token. Requests send it in the Authorization header.

  1. list_organization_projects — List organization projects.
  2. list_project_items — List project items.
  3. add_project_item — Add project item.

The definition references existing connector operations in the order above. Individual-step evidence does not establish that the composed workflow has been executed successfully. Inspect each result before continuing, and explicitly authorize any write step.

Run the local connector

Open source, with your own provider credentials. Provider API access and any provider charges remain yours. No PipMCP account is required for local execution.

Node.js22+ · terminal
git clone https://github.com/jannikco/github-projects-mcp.git
cd github-projects-mcp
npm ci --ignore-scripts
npm test
npm start

The default command shows the available operations offline. Provide GITHUB_TOKEN through environment variables or the supported local OS-vault resolver.

For a stdio MCP client, launch npm run server in the checkout. Open the released connector for full client configuration →
